# 协作流程 · 从下载到合并的完整操作手册

> 本手册面向第一次参与本项目的朋友。全程只用到 git 和 Node（玩游戏连 Node 都不用）。
> 有经验的老手看 [CONTRIBUTING.md](../CONTRIBUTING.md) 就够了；遇到问题看文末「常见问题」。

---

## 0. 两种参与身份

| 身份 | 适用 | 简述 |
|---|---|---|
| **Collaborator（协作者）** | 被仓库主人在 Settings → Collaborators 邀请的人 | 直接 clone 本仓库，建分支提 PR |
| **Fork 贡献者** | 仓库转公开后的路人 | 先 Fork 到自己账号，clone 自己的 fork，PR 回上游 |

下面以 Collaborator 身份为例（fork 流程只在第 1 步 clone 地址不同，其余一致）。

## 1. 一次性准备（约 5 分钟）

1. 注册/登录 [GitHub](https://github.com)，把用户名发给仓库主人，等待邀请邮件并在网页上点 Accept
2. 安装 [Git for Windows](https://git-scm.com/download/win)（一路默认即可，自带 Git Bash）
3. 安装 [Node.js LTS](https://nodejs.org/)（≥18，跑测试用；玩游戏不需要）
4. 打开 **Git Bash**，配置身份（只做一次）：
   ```bash
   git config --global user.name  "你的名字"
   git config --global user.email "你的邮箱"
   ```

## 2. 下载游戏（clone）

```bash
cd /d/Downloads        # 想放哪就 cd 到哪
git clone https://github.com/hualuochuanglingqian/abyss-corridor.git
cd abyss-corridor
```

clone 下来的就是**完整可玩的游戏**——双击 `index.html` 直接玩；改代码调试推荐起本地服务器（改完刷新即生效，不用清缓存）：

```bash
node tools/serve.js 8124     # 浏览器打开 http://127.0.0.1:8124/
```

## 3. 日常修改循环（背下这 8 步）

```
拉最新 → 建分支 → 改代码 → 自测 → 写修改日志 → 提交 → 推送 → 发 PR
```

### ① 同步最新代码（每次开工先做）
```bash
git checkout main
git pull origin main
```

### ② 建一个工作分支（一个功能一个分支，别在 main 上直接改）
```bash
git checkout -b feat/poison-blade     # 分支名建议: feat/xxx 新功能 · fix/xxx 修bug · balance/xxx 数值 · docs/xxx 文档
```

### ③ 修改代码
不知道去哪改？看 [README 目录结构](../README.md#-目录结构)。常用入口：
- 新武器/装备/词条 → `js/data/items.js` · `js/data/affixes.js`
- 新敌人/Boss → `js/data/enemies.js` · `js/systems/ai.js`
- 祝福/天赋/挑战 → `js/data/boons.js` · `js/data/talents.js` · `js/data/config.js`
- 数值难度 → `js/data/enemies.js` 的 `ENEMY_TUNING`

### ④ 自测（不过不许提交）
```bash
node tools/smoke.js          # 必须最后输出 ✅ 全部检查通过
node tools/build-single.js   # 改了任何 js/css 后跑一次，确认单文件版能构建
```
然后**真的玩一会儿**：起服务器实测你改的功能；动数值的再跑 `node tools/balance.js` 看胜率有没有失控。

### ⑤ 写修改日志（强制）
打开 [`CHANGELOG.md`](../CHANGELOG.md)，在顶部「未发布」小节按规范加一条——
面向玩家、一条一个变化、分类归档、行尾署名。**没有日志条目的 PR 会被打回。**

### ⑥ 提交（commit）
```bash
git add -A
git commit -m "feat: 新增毒刃词条 (40% 中毒)"
```
提交信息格式：`类型: 一句话摘要`，类型取 `feat / fix / balance / docs / art / refactor`。

### ⑦ 推送到 GitHub
```bash
git push -u origin feat/poison-blade
# 之后的推送只需: git push
```
首次推送会弹出浏览器让你登录 GitHub 授权（Git 凭据管理器），点一下就好。

### ⑧ 发 PR（Pull Request）
推送后打开仓库页面会提示 **Compare & pull request**，点进去：

**PR 描述模板（复制粘贴改一改）：**
```markdown
## 做了什么
- 一句话概括改动

## 自测情况
- [x] node tools/smoke.js ✅ 全部检查通过
- [x] 实机试玩: (描述你验证了什么)
- [x] 已在 CHANGELOG.md「未发布」添加条目

## 数值对比（改数值必填）
balance.js 前: F5 屠夫胜率 67%
balance.js 后: F5 屠夫胜率 60%
```

提交后 **CI 会自动跑完整回归**（页面下方出现小圆点），变绿✅才能请人合并，变红❌点进去看日志修完再推。

### ⑨ 合并之后
PR 被 merge 后删掉本地分支、拉最新，开始下一个功能：
```bash
git checkout main
git pull origin main
git branch -d feat/poison-blade
```

## 4. 修改日志写作速查

完整规范见 [CHANGELOG.md](../CHANGELOG.md) 文末，速记版：

> **每个 PR 一条 · 面向玩家 · 分类归档（新增/变更/修复/移除）· 行尾署名 · 数值改动贴 balance 对比**

## 5. 常见问题

| 症状 | 处理 |
|---|---|
| `git push` 卡住/报 403 | 你没被邀请为 Collaborator，或浏览器授权没完成；重推一次会再弹登录窗 |
| CI 红灯 | 点 PR 页 Checks → 失败的那条 → 看日志最后 20 行；十有八九是 `smoke.js` 某条断言，本地复现修掉再推 |
| 和别人改冲突了 (merge conflict) | `git checkout main && git pull && git checkout 你的分支 && git merge main`，手工解决标 `<<<<<<<` 的文件后 `git add` + `git commit`，再推 |
| 改砸了想全部重来 | 分支还没 push：`git checkout main && git branch -D 分支名`；已 push：直接在 GitHub 页面关掉 PR 即可，没有任何损失 |
| 游戏改坏了打不开 | F12 看控制台红色报错，贴到 issue/群里；或者 `git checkout main` 回到能玩的版本 |
| 想提 bug 但不会改 | 开 Issue：写明种子（顶栏🌱）、复现步骤、F12 报错截图 |

## 6. 项目约定（红线）

1. **零依赖**：不引第三方库/素材/字体；图形程序化绘制、音效合成
2. **file:// 双击必须能玩**：不用 ES module、不发网络请求
3. **存档兼容**：动存档结构必须升版本并写迁移，旧档能读
4. **中文文案**：UI/日志保持中文，风格参考现有条目
